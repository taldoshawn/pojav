# Horizon `.hnmod` Compiler, Android Hot-Swap Loader & Java-to-HNMOD Transpiler Guide

## 1. Why `.hnmod` Files Made Earlier Did Nothing (The Real Secret in Horizon)

In Horizon / Horizon (`horizon-core/docs/horizon-native-mods.md`), an **`.hnmod` file is NOT loaded dynamically like a script or `.jar` at runtime**.
An `.hnmod` is a **Rust source-code mixin bundle (`horizon-mixins`)** that modifies Horizon's Rust source tree BEFORE `cargo ndk` compiles `libhorizon_android.so`!

For `.hnmod` mods to actually run on Android, **two halves** are required:

### Half A — Inside Horizon Android (Launcher / Game Client)
1. **In-Game `.hnmod` Compiler Client (`crates/horizon-client/src/game/native_builds.rs`)**:
   - Scans `horizon-native-mods/*.hnmod`. Any `.hnmod` not compiled into the currently running `libhorizon_android.so` gets a **"Compile"** button in Options > Mods (`crates/horizon-client-render/src/mod_list.rs`).
   - Clicking **Compile** packs the `.hnmod` files (4-byte big-endian length + zip bytes) and `POST`s them to `${HORIZON_BUILD_SERVER}/v1/build?version=${version}`.
   - Polls `/v1/job/<job_id>`, downloads the compiled `libhorizon_android.so` from `/v1/job/<job_id>/lib` (with HTTP `Range` resume and SHA-256 verification), saves it to `files/native/compiled-<job_id>/libhorizon_android.so`, and writes `compiled-<job_id>` to `files/native/current`.
2. **Dynamic `libhorizon_android.so` Hot-Swap at Startup (`NativeMods.java` + `HorizonActivity.java` + `android.rs`)**:
   - In `HorizonActivity.onCreate()`, BEFORE `super.onCreate()`, `loadGame()` calls `NativeMods.chosen(this, versionName())`.
   - When `files/native/current` exists and matches the app version, it sets `Os.setenv("HORIZON_GAME_LIBRARY", build.getPath(), true)` and calls `System.load(build.getPath())` instead of `System.loadLibrary("horizon_android")`.
   - When Android's `NativeActivity` invokes `horizon_on_create` (`crates/horizon-client/src/android_lib.rs` -> `android.rs`), `android::on_create` reads `HORIZON_GAME_LIBRARY`, calls `dlopen(path, RTLD_NOW)` and `dlsym(build, "ANativeActivity_onCreate")`, and hands execution over to the custom-compiled `libhorizon_android.so`!
   - **2-Strike Crash Guard (`NativeMods.java`)**: `NativeMods.chosen()` increments `files/native/starts`, and `HorizonActivity.firstFrame()` deletes `files/native/starts` once the first frame renders. If a bad mod crashes twice before the first frame (`TRIES = 2`), `NativeMods.java` automatically clears `files/native/current` and boots the stock APK library with an explanation notice!

### Half B — The Real `.hnmod` Compiler (`native_build.sh` + `native_mod_adapt.py` + `launcher/src/native_mods/`)
When `.hnmod` bundles are compiled into `libhorizon_android.so` (or desktop `horizon-client`):
1. **Crate-Split & Signature Auto-Adapter (`packaging/android/native_mod_adapt.py`)**:
   - Automatically rewrites legacy `horizon_client::<module>` targets to the split crates (`horizon_client_render`, `horizon_client_core`, `horizon_client_input`, `horizon_client_lib`) and updates changed method calls so mods written against different commits still compile cleanly.
2. **Typed `mod_api` (`Hooks` & `Host` Trait API in `crates/horizon-client/src/mod_api.rs` & `launcher/src/native_mods/api.rs` + `inject.rs`)**:
   - In addition to raw `horizon-mixins` helper snippets (`[[injection]]`), Horizon adds `horizon_client::mod_api::{Hooks, Host}` (generated by `xtask/src/mod_api.rs` from `native-hooks.json` with 100+ hooks!).
   - A mod can implement `Hooks` (`fn tick`, `fn key`, `fn destroy_block`, `fn right_click_block`, `fn hud`, `fn living_incoming_damage`, `fn loot_drops`, etc.) and call `host.set_block(...)`, `host.give_items(...)`, `host.spawn_mob(...)`, `host.tell(...)`, `host.action_bar(...)`, `host.draw_cube(...)`, etc., OR inject directly into `Game` methods like `native-mods/wrench` does!
3. **Incremental Build Cache (`packaging/android/native_build.sh`)**:
   - Temporarily replaces `crates/horizon-android/Cargo.toml` `path = "../horizon-client/src/android_lib.rs"` with an empty `plan-stub.rs` while `horizon-mixins apply` runs (preventing `E_TARGET_AMBIGUOUS`), then `rsync --checksum`s only modified files into `$NATIVE_CACHE/build` and runs `build_apk.py --profile fast --library-only` so Cargo only recompiles the touched crate (`~35-50s` instead of 15 minutes)!

## 2. How Horizon's Rate Limits Worked — And How Our Horizon System Eliminates Them

In Horizon's `packaging/android/mod_build_gateway.py` and `mod_build_server.py`:
- `PER_ADDRESS = 16` (blocked any user after 16 builds/day with HTTP 429 `"That is enough builds for today. Try again tomorrow."`)
- `FAILED_PER_ADDRESS = 24` (blocked after 24 failed builds/day)
- `PER_DAY = 80` (blocked everyone globally after 80 builds/day)
- `if any(jobs[k].get("client") == client for k in line): raise Refused("You already have a build in line.")` (blocked parallel/queued builds from the same user)
- Hardcoded `BUILD_SERVER = "https://191-234-193-205.sslip.io"` in `native_builds.rs`.

**In our owned system (`unlimited-compiler-server/mod_build_server_unlimited.py` + IDE & Launcher integration)**:
1. **Zero Rate Limits**: All `PER_ADDRESS`, `FAILED_PER_ADDRESS`, `PER_DAY`, and single-job-per-IP locks are completely removed.
2. **Custom / Local / Cloud Build Server + GitHub Actions Fallback**:
   - Users and the IDE can point `HORIZON_BUILD_SERVER` (or the Settings URL in the IDE/Launcher) to our own unlimited `mod_build_server_unlimited.py` instance, a local Linux/Termux/Desktop compiler (`native_build.sh`), or trigger `.github/workflows/native-mods.yml` on GitHub Actions to build `libhorizon_android.so` for free on GitHub's servers!
